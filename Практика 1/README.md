# Эмулятор UNIX-оболочки — вариант №20

Практическая работа по дисциплине **«Конфигурационное управление»**.
РТУ МИРЭА, группа **ИКБО-16-25**. Основа — сборник П.Н. Советова,
2026/2027 учебный год, стр. 65–67.

## Описание

Программа имитирует ограниченный набор UNIX-команд в графическом интерфейсе
Tkinter. В отличие от настоящей оболочки, команды работают с виртуальной
файловой системой (VFS), загруженной из JSON **целиком в память**. `cp` меняет
только дерево в оперативной памяти и не переписывает исходный JSON-файл.

Проект реализован на **Python 3** только со стандартной библиотекой.
Для отображения окна требуется Tkinter (на Windows обычно входит в Python;
на некоторых дистрибутивах Linux устанавливается отдельно).

## Что выполнено по этапам

1. **REPL.** Окно с названием `Эмулятор - [username@hostname]`, ввод
   и вывод, разбор команд и переменных окружения `$HOME`, `${NAME}`,
   ошибки неизвестных команд и синтаксиса, `exit`. В первом коммите
   команды `ls` и `cd` сделаны заглушками.
2. **Конфигурация.** Ключи `--vfs` и `--script`, отладочный вывод
   параметров при запуске, сценарии с комментариями `#`, сообщения
   об ошибках с номером строки, `.bat`/`.sh` для вариантов запуска.
3. **VFS.** Загрузка JSON-дерева без распаковки, двоичные данные — base64.
   Три проверочных варианта: пустой, с несколькими файлами, с глубокой
   иерархией каталогов. Валидация структуры и обработка ошибок.
4. **Основные команды.** Рабочие `ls`, `cd`, `tac`, `date`, `clear`.
5. **Дополнительная команда.** `cp` (файлы, каталоги через `cp -r`)
   с изменениями исключительно в памяти.

Дополнительно добавлена `echo` для наглядной демонстрации раскрытия
переменных окружения; в методичке для варианта №20 она не обязательна.

## Быстрый запуск в Windows

Установить Python 3 с поддержкой Tkinter. Открыть **PowerShell** в корне
проекта и выполнить:

```powershell
py -3 -m src.main
```

Или дважды нажать `run.bat` (при установленном Python Launcher `py`).
Для запуска полной демонстрации:

```powershell
py -3 -m src.main --vfs data/nested.json --script scripts/startup_full.txt
```

Либо нажать `scripts/run_full.bat`.
Другие варианты: `scripts/run_minimal.bat`, `scripts/run_simple.bat`,
`scripts/run_nested.bat`, `scripts/run_errors.bat`.

## Запуск в Linux/macOS

```bash
./run.sh
./run.sh --vfs data/nested.json --script scripts/startup_full.txt
./scripts/run_full.sh
```

Если `python3 -m tkinter` выдаёт ошибку, установить пакет Tkinter для
вашей ОС. Для обычного запуска нужен рабочий графический дисплей.

## Параметры

| Параметр | Назначение |
|---|---|
| `--vfs ПУТЬ` | JSON с деревом файлов (по умолчанию `data/nested.json`) |
| `--script ПУТЬ` | Выполнить команды из текстового файла при старте |
| `-h`, `--help` | Вывести справку аргументов запуска |

При запуске в окне выводятся фактически переданные значения параметров.
Стартовый сценарий выполняет команды последовательно, показывает
**введённые строки и полученные результаты**, игнорирует пустые строки,
а строки `#` рассматривает как комментарии. Ошибка команды выводится на
экран с номером строки, после чего демонстрация продолжает работу.

## Команды и примеры

| Команда | Что делает | Пример |
|---|---|---|
| `ls [путь]` | Список файлов и папок | `ls docs` |
| `cd [путь]` | Изменить текущую VFS-папку | `cd docs/notes` |
| `tac ФАЙЛ...` | Показать строки файлов в обратном порядке | `tac lines.txt` |
| `date [+FORMAT]` | Локальное время реальной ОС | `date +%Y-%m-%d` |
| `clear` | Очистить окно терминала | `clear` |
| `cp [-r] ИСТОЧНИК НАЗНАЧЕНИЕ` | Копировать внутри VFS | `cp hello.txt backup.txt` |
| `echo ТЕКСТ` | Дополнительная команда, показать текст | `echo "$HOME"` |
| `exit` | Закрыть окно | `exit` |

Пример последовательности команд внутри окна:

```text
ls
cd docs
ls
cd notes
tac lines.txt
cd ../..
cp hello.txt backup.txt
ls
cp -r docs docs-copy
ls docs-copy/notes/archive
date +%Y-%m-%d
echo "$HOME"
```

Обрабатываются абсолютные (`/docs`) и относительные (`notes`, `..`) пути.
Если у `cp` назначение — каталог, копия создаётся внутри него. Уже
существующий файл можно заменить копией другого файла. Для копирования
каталога нужен флаг `-r`. Нельзя скопировать каталог внутрь самого себя.

**Ограничения учебного эмулятора:** это не полноценный Bash. Нет
конвейеров, перенаправлений, подсистемы прав и операций с реальной ФС.
Парсер понимает кавычки, пробелы, `#`-комментарии и раскрывает `$NAME`
и `${NAME}`; даже одинарные кавычки не запрещают подстановку переменных,
что упрощает правила по сравнению с Bash. Переменная `$HOME` указывает
на домашний каталог **реальной** ОС, но не на каталог внутри VFS.

## Формат JSON и base64

```json
{
  "name": "example",
  "root": {
    "type": "dir",
    "children": {
      "hello.txt": {"type": "file", "data": "SGVsbG8K"}
    }
  }
}
```

Каталог имеет `"type": "dir"` и объект `"children"`.
Файл имеет `"type": "file"` и строку `"data"` в base64.
Пример данных `SGVsbG8K` кодирует текст `Hello` с переводом строки.

## Автоматические тесты

Windows, PowerShell:

```powershell
py -3 -m unittest discover -s tests -v
```

Linux/macOS:

```bash
python3 -m unittest discover -s tests -v
```

Тестируются парсер, обработка ошибок, входные параметры, комментарии,
три вида VFS, двоичные файлы, навигация, `tac`, `date`, `clear`,
копирование файлов и каталогов и **неизменность JSON на диске**.

## Git и сдача

Этапы сохранены **пятью отдельными локальными коммитами** в формате
Conventional/Scoped Commits. Посмотреть историю:

```bash
git log --oneline --reverse
```

Чтобы отправить репозиторий в GitHub, сначала создать **пустой**
репозиторий на GitHub (без создания README и .gitignore на сайте),
затем в каталоге проекта выполнить (подставить свой URL):

```bash
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

`.gitignore` исключает служебные файлы Python и редакторов. В Git
попадают исходный код, JSON-образцы, тесты, сценарии и инструкция;
архив проекта, который предоставляется для скачивания, **не хранится
внутри git-репозитория**.
